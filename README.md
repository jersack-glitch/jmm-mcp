# JMM MCP

Custom MCP server for the Jeremy Management Model. Runs as a Supabase Edge Function.

## Setup on a new machine

1. Install Supabase CLI: brew install supabase/tap/supabase
2. Clone this repo: git clone <repo-url>
3. Link to project: supabase link --project-ref <project-ref>
4. Apply migrations: supabase db push (or paste supabase/migrations/*.sql into the SQL editor — they are idempotent)
5. Deploy: supabase functions deploy jmm-mcp

## Structure

- supabase/functions/jmm-mcp/index.ts — the MCP server
- supabase/migrations/ — schema migrations (memory semantic search lives here)
- supabase/config.toml — Supabase project config

## Semantic layer

The `memory_semantic_search` migration adds fuzzy retrieval over exactly three
tables — `memory`, `cross_insight`, `writing_piece`. Operational state
(`thread`, `project`, anything reaching BMM) is deliberately excluded: semantic
retrieval over operational tables returns plausible neighbors instead of
correct rows, so priorities, deal state, and waiting_on stay deterministic SQL.

- **Embeddings** — 384-dim `gte-small` vectors generated by this edge function
  via `Supabase.ai` (built into the edge runtime, no external API key),
  pgvector + HNSW-indexed.
- **memory** — the fuzzy-retrieval gap: `memory_recall()` (hybrid vector +
  keyword, weighted by importance/recency/usage), `memory_find_similar()`
  (write-time dup flagging), `memory_mark_referenced()` (reinforcement:
  retrieval bumps `last_referenced`/`reference_count`, which feed ranking),
  and lifecycle columns (importance 1–5, active/archived).
- **cross_insight** — fixes a live defect: `signature_hash` is exact-match, so
  a reworded insight inserted as a new row and `occurrence_count` never bumped,
  breaking the recurrence signal. `insight_find_similar()` powers semantic
  dedup before insert (cosine ≥ 0.90 → bump the existing row instead).
- **writing_piece** — thematic adjacency across manuscript/Substack/LinkedIn:
  `writing_find_similar()` proposes `writing_connection` edges from the index
  (with already-linked awareness) instead of from memory.
  `writing_embedding_backlog()` tracks rows edited after their last embedding.
- **corpus_adjacent()** — cross-domain adjacency in one call: nearest neighbors
  across all three embedded tables, labeled by source, for insight synthesis
  without reading the corpus into context.

### Function tools

POST the function with `{ "tool": "<name>", "args": { ... } }` (Bearer: anon or
service key, since `verify_jwt = true`):

| Tool | Purpose |
|---|---|
| `add_jeremy_memory` | Guarded write (requires `approved: true`); embeds + dup-checks |
| `add_claude_memory` | Free write to the Claude layer; embeds + dup-checks |
| `recall_memory` | Hybrid semantic recall; `{ query, layer?, tag?, limit?, min_score?, reinforce? }` |
| `embed_text` | Embedding service for the Node servers; `{ texts: string[] }` → 384-dim vectors |
| `backfill_embeddings` | The nightly job: embeds memory + cross_insight + writing_piece (incl. stale writing rows); `{ batch_size? }` |
| `backfill_memory_embeddings` | Memory-only backfill, kept for compatibility |
| `get_priorities` / `get_stalled` | Triage queries (unchanged) |

### The nightly embedding job

Everything new embeds at write time where the write goes through the JMM
servers; the nightly job covers the rest (rows written by the weekly review
job, writing pieces edited since their last embedding) and any writes that
happened while the embed service was down.

Schedule it in the Supabase Dashboard → Integrations → **Cron** → new job →
HTTP request (or invoke the edge function directly), nightly, e.g. `0 8 * * *`
(08:00 UTC ≈ overnight US):

- URL: `https://<project-ref>.supabase.co/functions/v1/jmm-mcp`
- Headers: `Authorization: Bearer <anon-key>`, `Content-Type: application/json`
- Body: `{"tool": "backfill_embeddings", "args": {}}`

Manual drain (first run after applying the migration):

```bash
while :; do
  out=$(curl -s -X POST "https://<project-ref>.supabase.co/functions/v1/jmm-mcp" \
    -H "Authorization: Bearer <anon-or-service-key>" \
    -H "Content-Type: application/json" \
    -d '{"tool": "backfill_embeddings", "args": {}}')
  echo "$out"
  echo "$out" | grep -q '"done": true' && break
  sleep 2
done
```

Batches are small on purpose: edge workers have a per-invocation compute
budget, and `batch_size` applies per table (capped at 10; 50 hit
`WORKER_RESOURCE_LIMIT` in production). Rows persist as they embed, so a
killed invocation loses nothing — the loop just keeps going until
`done: true`.

Everything degrades gracefully: before the migration is applied (or if
`Supabase.ai` hiccups), writes fall back to the legacy shape and callers are
told what happened instead of failing.
